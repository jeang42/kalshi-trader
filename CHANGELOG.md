## [Unreleased]

### Added

- **Bulk Deep Analysis runner (`bulk_deep_analysis.py`) + six staggered cron entries.** Walks the closing-soon market universe each night and runs `llm_deep_analysis.analyze_market` on every market in the batch (default 50) for one model per invocation. Cron lines at 2am-7am cover the six recommended models on the same nightly universe, producing the head-to-head Brier-per-model dataset that will eventually inform which model to promote to live triggers. Forecast-only by design — no paper trades. Logs to `agentic_deep` profile tagged `llm_deep:<model>`. Skips markets this model already analyzed in the last 12h to avoid duplicate rows. Default Ollama timeout bumped to 300s (the 120s default in `llm_data` was tripping on 35B models with full context). `qwen3.5:35b` added to `RECOMMENDED_MODELS` as the new top-of-list. 7 new unit tests cover happy path, max-markets cap, profile save/restore, None-result handling, partial-failure isolation, recency skip, and the CLI entry.

- **Estimated cash-out column on Live Portfolio.** For each held position, computes value you'd receive selling at the current bid right now: cash-out $ value, unrealized PnL vs cost (both $ and %), and a status icon (🔒 = market closed, value from last trade; ⚠️ = no signal). Pure read; no API writes. New `kalshi_client.estimate_cashout(position, yes_bid, yes_ask, last_trade, cost_basis_cents)` helper drives it. Page summary shows total cost basis + total cash-out value + aggregate unrealized PnL. 6 new tests.

- **Deep Analysis model picker improvements.** Recommended models pinned to the top of the picker in priority order (`qwen3:32b` → `qwen2.5:32b` → `deepseek-r1:32b` → `gemma3:27b` → `qwen2.5:14b` → `llama3.1:latest`); default selection is the first one actually pulled. Non-chat models (embed / vision / captioner) filtered out by default with a sidebar toggle to show everything. Ollama 500 responses now surface the actual server body in the UI (was previously a silent stop). 6 new tests for the sorting + default-selection helpers.

- **Auto-resolve as cron** (`auto_resolve_runner.py` + 15-min cron entry). Walks every profile and marks pending forecasts whose tickers have resolved. Calibration data was accumulating but auto-resolution only fired when you clicked the button on the Calibration page — Track Record badges said "untested" not because no resolutions had happened, but because nothing told the system. The runner builds a merged closed-markets lookup ONCE on the owner profile (so Kalshi settlement data is visible to all profiles, not just the auth owner — a real architectural fix the page version didn't have), then walks each profile in turn. Save/restore of the user's UI-selected profile around the run, like the other runners. Verified live: resolved 3 pending Massie forecasts across `jeff`, `agentic`, and `agentic_llm` in one cycle. 11 new tests cover provider union, error isolation, settlements overlay, lookup precedence, save/restore, and the main-loop exit codes.

- **🌐 Phase B of Deep Analysis — web-fetched context.** New `web_context.py` adds two free unauthenticated sources: Google News RSS for recent headlines on the market subject, Wikipedia REST API for an entity summary derived from the question text (best-effort via the em-dash suffix from `_compose_question`). `analyze_market` gains `include_web_context: bool` kwarg; Deep Analysis page renders a "🌐 Add web context" checkbox alongside the existing "Bypass cache". System prompt updated to demand the model cite specific headlines / Wiki passages in `evidence_used` when web context is supplied — same honesty rule as Phase A but explicit. Cache integrated into the existing `llm_cache` SQLite (6h TTL for news, 7d for wiki). Verified live against the KY-4 Massie market: with web context off llama3.1 said "probability 0.45 / WAIT"; with web context on it picked up the WaPo headline "Massie loses GOP primary" and switched to "probability 0.000 / HIGH confidence / BUY_NO" citing the headline. 15 new unit tests + 2 new live smoke checks; the round-trip live-order smoke now picks a dynamic long-dated target so it doesn't break when the previously-pinned market closes.

- **🧠 Deep Analysis page + `llm_deep_analysis.py`.** Slow per-market structured-reasoning pipeline complementing the fast batch Edges / Recommendations forecasts. Picks one market, gathers context (price history summary, market metadata + resolution criteria, order book depth, sibling sub-markets), packs it all into a single long prompt, asks the local LLM for a JSON `DeepAnalysis` with probability + confidence + key_drivers + key_risks + evidence_used + recommended_action + reasoning. Save-to-calibration button tags forecasts as `llm_deep:<model>` so the source has its own Brier track separate from the fast `llm:<model>` line. Cached 24h on (ticker, model, context-hash); bypass-cache checkbox forces a fresh run. Phase A is local-context-only by design — web-fetched context (news, Wikipedia) deferred to Phase B once Phase A's outputs are validated against real resolutions. 16 new tests cover response parsing, context summarizers, and end-to-end with mocked Ollama.

### Changed

- **Renamed Portfolio → Sandbox Portfolio.** The sidebar label and page title now read "Sandbox Portfolio" so it can't be confused with the real-money Live Portfolio. Caption added explaining the page is the paper-trade log; users should look at 🏦 Live Portfolio for their actual Kalshi state. Filename stays `portfolio.py` (no URL break).

- **Bulk Deep Analysis category diversity.** Sorting purely by liquidity was collapsing each nightly batch onto Sports (NHL series spreads + MLB games dominate the high-liquidity end). Now takes up to `max_markets / n_categories` from each category in liquidity-descending order, then fills any remainder from the unallocated tail. Logs the resulting breakdown each cycle. One new test verifies diversity when Sports has 5× the liquidity of every other category. Default model also reverted to `qwen3:32b` (faster, similar quality vs the 35B); `qwen3.5:35b` stays in the nightly cron rotation but is no longer the interactive picker default.

### Fixed

- **strategy_runner race condition on the shared `.active_profile` file.** The earlier save/restore-around-main fix doesn't protect against concurrent cron runs. Three strategy runners fire on overlapping schedules; if runner A switches active profile, runner B reads `.active_profile` mid-cycle and B's writes land in A's profile. Result: jeff's paper portfolio had 54 cron-induced favorite_grind trades totalling $— — none user-initiated. New `_pin_profile_env` sets `POLYMARKET_PORTFOLIO_FILE` / `FORECASTS_FILE` / `ALERTS_FILE` to the target profile's paths inside `run_cycle`, making storage process-local. Respects pre-existing overrides so tests still work. 23/23 strategy_runner tests green.

- **Kalshi `liquidity_dollars` is broken — Market Scanner empty.** The field returns `"0.0000"` on every Kalshi market, including ones with 11M+ open interest. With the scanner's default `min_liquidity=$500` floor, every Kalshi market got filtered out → all four scanner tabs returned empty 100% of the time. `_market_to_row` now falls back to `max(volume_24h_fp, 0.1 × open_interest) × yes_mid` as a $-denominated activity proxy when `liquidity_dollars` is zero. Live verified: 29/500 markets clear the $500 floor (vs 0 before). Smoke test gains a regression guard: at least 5 markets must show `liquidity ≥ $500`.

- **Settlements revenue double-conversion.** Kalshi's settlement responses have `revenue` as an integer already in cents (3300 = $33.00), unlike most other numeric fields which are dollar-suffixed strings. `_dollars_to_cents` was multiplying by 100 again, displaying a real settlement 100× too large. Now checks `revenue_dollars` first (string path) and falls back to `revenue` (int path). Two regression tests cover both shapes.

- **Kalshi authed field mapping bug.** `get_authed_positions` / `get_fills` / `get_settlements` were reading bare field names but Kalshi returns type-tagged suffixes (`position_fp`, `market_exposure_dollars`, etc.). Every numeric was silently returning 0 — the Live Portfolio showed position=0 / exposure=$0 even when the user held a real position with $— exposure. New `_dollars_to_cents` and `_fp_to_int` helpers coerce the typed strings; all four endpoint wrappers updated with bare-name fallback. Smoke test gains a regression guard: when positions exist, at least one numeric must be non-zero.

- **`expected_expiration_time` preferred over `close_time`.** Kalshi has three date fields; we were using `close_time` (the latest-possible-resolution backstop, often months out) instead of `expected_expiration_time` (real expected resolution). The KY-4 Massie market showed as "168 days out" when it actually resolved in 0.4 days on its early-close trigger. Affects every page's days-to-resolution filter, the LLM prompt's date awareness, and the agentic runner's min-days-to-expiry guard. Also adds `TODAY` + `EXPECTED RESOLUTION` + `EARLY-CLOSE TRIGGER` fields to the Deep Analysis prompt so the model can reason about timing properly.

- **Closing-soon results had blank categories.** Kalshi's per-game events sit beyond our `/events` scan window. Now falls back to keyword inference via `polymarket_client._infer_category` when the event lookup misses; 500 short-dated markets distribute as Sports / Other / Finance / Politics / Geopolitics instead of all blank.

- **Cron-fired `strategy_runner` was stealing the UI's active profile.** Every 30 min it'd overwrite `data/.active_profile` with the runner's profile, hijacking the user's sidebar selection. `main()` now wraps the run in a save/restore. Two regression tests.

- **Order placement: three bugs caught during the first live trade.** `time_in_force: "gtc"` rejected by Kalshi (omit it; defaults to GTC). Side derivation wrong on the No-outcome row (combines outcome row × direction now). HTTPError body was being swallowed; now surfaced in the UI and the audit log so the rejection reason ("invalid_parameters", "market_closed", "insufficient_balance") is visible.

- **Streamlit deprecation cleanup.** Replaced `use_container_width=True` with `width='stretch'` across all 12 call sites (removed after 2025-12-31).

- **Quieter logs.** Demoted 429 retry messages from `warning` to `debug` — the retry path works correctly so they were noise. Set `POLYMARKET_LOG_LEVEL=DEBUG` to see them again.

- **429 caching + binary-market slider simplification.** Module-level TTL cache (5 min) on the `/events` scan inside `get_markets_closing_within` cuts smoke-test rate-limit retries from ~10 to ~2 (80% reduction); every caller in the process shares one scan. Kelly Sizer now renders one slider on binary Kalshi markets instead of two — the second carried identical mirrored information and was a UX trap. Multi-outcome markets keep the per-outcome loop.

## [0.2.0-alpha.1] — 2026-05-19

First alpha release with live trading. Kalshi authentication, real order placement (manual-confirm only), reconciliation, recommendations from five Tier-4 sources, and a live-API smoke test. **Not yet recommended for unattended use** — the agentic runners still write to paper profiles, and Phase 3 (slippage ground truth from real fills) and Phase 5 (automated execution) are deferred until a track record accumulates.

### Fixed

- **Live order placement: three bugs caught during the first live trade attempt.** (1) Kalshi rejects `time_in_force: "gtc"` with a 400 — its validator's `oneof` tag doesn't include it. Removed the field entirely; omitting defaults to good-till-cancelled. Verified live with a 1-contract place+cancel test. (2) Order panel's side derivation was wrong on the No-outcome row: both outcome rows refer to the same Kalshi ticker but the API's `side` is the contract type being bought, not "bet for/against this outcome." Fixed by combining outcome row × Kelly direction so all four cases (Yes/No row × YES/NO direction) map correctly. (3) UI was showing only `str(HTTPError)` for Kalshi rejections, losing the response body where the human-readable reason lives. `place_limit_order`'s audit log + the Kelly Sizer's error toast now both capture `response.text` so the user sees the actual rejection reason.

- **Cron-fired `strategy_runner` was stealing the UI's active profile.** Every 30 minutes it'd overwrite `data/.active_profile` with the runner's profile (e.g. `agentic_llm`), hijacking the user's sidebar selection. `main()` now wraps the run in a save/restore so the prior selection survives on normal exit, error, and signal. Two regression tests.

- **Kalshi market display: multi-outcome events were showing the umbrella title repeated.** A multi-outcome event like "Who will the next Pope be?" has one binary YES/NO sub-market per candidate, but `_market_to_row` was setting `question` to the event-level `title` only. `_compose_question` now joins `title + " — " + yes_sub_title` so each sub-market reads as a distinct YES/NO question ("Who will the next Pope be? — Pierbattista Pizzaballa"). Falls back to title alone for true binary markets where the sub-title is empty / boilerplate / duplicate.

- **Closing-soon results had blank categories** when the user filtered by max-days. Kalshi's per-game events sit beyond our `/events` scan window, so the event-side lookup returned nothing for short-dated markets and the category filter saw "All sports" → 0 results when narrowed. Falls back to keyword inference via `polymarket_client._infer_category` when the event lookup misses. Verified live: 500 short-dated markets now distribute as Sports / Other / Finance / Politics / Geopolitics.

### Added

New `kalshi_orders.py` exposes `place_limit_order` / `cancel_order` / `get_resting_orders` plus a pure `pre_flight_check` returning `(severity, msg)` tuples for fail-loud guardrails (stake cap default $50, daily cap default 10 orders, fat-finger price-band check default ±10¢ from mid, drawdown circuit-breaker, invalid count/price). `kalshi_auth.py` gains `authed_post` / `authed_delete` helpers — same retry/error semantics as `authed_get` plus 4xx body logging since order rejections carry human-meaningful reasons. Multi-outcome (candidate-name) markets fall through silently — Phase 2 is binary-only. Refuses to load a PEM with group/world-readable permissions (prevents the most common leak failure mode). `kalshi_client.py` gains four authenticated wrappers: `get_balance`, `get_authed_positions`, `get_fills`, `get_settlements` — all returning normalized DataFrames. - **Third agentic profile running the LLM forecaster (Tier-4 source).** New cron entry runs `strategy_runner --strategy llm_forecast --profile agentic_llm` every 30 min (offset by 15 min to spread load with the other two runners). The strategy is the existing `llm_forecast` Tier-4 source — uses local Ollama (no API cost), benefits maximally from the persistent LLM cache (cycle-2 onward should be mostly cache hits while prices haven't moved). Tighter knobs than the other runners: 5% per-position cap (LLM mistakes can be dramatic on small-cap markets) and `min_days_to_expiry=2.0` to filter near-resolution markets where the LLM's NO conviction can produce a fake +99pp gap against an already-settled market. The third profile auto-created via the `agentic_*` prefix convention; Settings banner picks it up via `is_agentic_profile()`.

- **`--strategy-arg key=value` CLI flag** on `strategy_runner.py`. Repeatable; values coerced int → float → bool → str (model names with colons like `qwen2.5:14b` correctly stay strings). Bound via `functools.partial` so the kwargs shadow strategy defaults for every per-market call in the run. Enables tuning without editing source: `--strategy-arg model=qwen2.5:14b --strategy-arg min_gap=0.05 --strategy-arg min_days_to_expiry=2.0`. 10 new tests cover the parser (empty list, int/float/bool/string coercion, multiple args, bare-key-is-true, empty-key-skipped, whitespace-trimmed) plus an integration test verifying kwargs actually reach the strategy via functools.partial.

- **Favorite-grind strategy + second agentic experiment.** New `user_strategies/favorite_grind.py` plugin bets whichever side is favored above a threshold (default 0.85) with a small assumed edge (default 0.02). It's intentionally the "picks pennies in front of a steamroller" archetype — high volume, tiny per-trade margin, asymmetric tail (one miss on a 95% favorite costs ~19 wins to recover). Whether it works empirically depends on whether favorites are systematically under-confident; the Calibration page's Brier-by-source breakdown will tell us. Profile-naming convention generalized via `profiles.is_agentic_profile(name)` — matches the bare `agentic` profile plus any `agentic_*` variant so parallel experiments get their own state without each one needing explicit registration. Settings page banner uses the new helper. Cron extended with a second `strategy_runner` entry: `*/30 * * * * ... --profile agentic_favorites --strategy favorite_grind --max-position-pct 0.05 --min-gap 0.02 --max-markets 100`. Smaller per-position cap (5%) because favorite-grinding stakes large at low edge; smaller min-gap (0.02) because the strategy's default assumed_edge is 0.02. Live single-cycle on Polymarket: 30 markets scanned → 27 signals → 3 actually opened (rest clipped by Kelly+spread shrinking the stake below cap), all on 89-94% favorites. 9 new tests: 6 on the plugin's decision boundaries (fires YES on high favorites, NO on extreme lows, no-signal in the middle, threshold parameter respected, clamps probability to ≤0.99) plus 3 on the `is_agentic_profile` helper (bare name, prefixed variants, lookalikes correctly rejected).

- **Agentic profile + strategy runner.** New `agentic` default profile and `strategy_runner.py` script — a cron-able runner that picks a registered strategy and records its signals as forecasts (to `calibration`) + paper buys (to `portfolio`) inside the chosen profile. Per cycle: (a) scans `provider.list_providers()` for closed markets and auto-closes any held positions at $1/$0 + auto-resolves matching forecasts via the existing `calibration.auto_resolve_pending` plumbing; (b) pulls active markets, runs the strategy, and for each non-existing-position signal whose Kelly-sized stake clears `--min-gap` records a forecast + buy. Per-market position cap (`--max-position-pct`, default 10%) keeps the runner from over-concentrating; the existing-position-set check makes the cycle idempotent so cron re-runs don't double-buy. CLI mirrors `book_poller.py`: single cycle by default (cron-friendly), `--loop --interval` for systemd/tmux. Settings page renders an "🤖 Agentic profile" warning banner when the active profile is in `profiles.AGENTIC_PROFILES`. **Installed in cron alongside the book poller**: `*/30 * * * *` with `market_consensus` into the agentic profile so the experiment ("what would full automation produce?") starts accumulating data immediately. Live single-cycle verified on Kalshi: 5 markets scanned → 5 signals → 5 positions opened + 5 forecasts logged in 0.2s. 8 new tests cover snapshot synthesis, the signal-to-buy-and-forecast path with mocked provider, existing-position skip, min-gap thin-edge filter, max-position-pct cap, and the close-on-resolution path for both won and lost outcomes.

- **User-defined strategy plugins.** New `backtest.register_strategy(key, display_name)` decorator + `discover_user_strategies()` scanner. Drop a Python file in `user_strategies/` with one or more `@register_strategy`-decorated functions and they appear in the Backtest page's strategy dropdown on the next reload — no edits to `backtest.py` required. Discovery is idempotent (Python caches imports) and broken plugin files are logged + skipped rather than crashing the app. Underscore-prefixed modules are skipped so shared helpers don't accidentally try to register. Includes `user_strategies/example_buy_low_yes.py` as a copy-paste starter showing the minimal shape, plus an `__init__.py` documenting the contract. 10 new tests cover the decorator (registration, function unchanged, default display name, override-with-warning, empty-key rejection) and the discovery loop (missing dir, single-strategy happy path, broken-plugin logged-and-skipped, underscore-prefixed-skipped, idempotent re-import).

### Fixed

- **Backtest page was silently missing Tier-4 strategies when visited before Edges.** Tier-4 strategy registration (`crypto_spot_lognormal`, `llm_forecast`, `sports_winprob`, `manifold_community`, `macro_threshold`) happens as a module-load side effect inside `edges.py`. Previously `edges` was imported only by `pages/edges.py`, so any user who visited the Backtest page first saw a strategy dropdown with only the in-process baselines + plugins. `app.py` now imports `edges` at startup so the side effect runs before any page renders.

### Fixed

- **Backtest engine now enforces a portfolio-level bankroll constraint.** Single-shot and walk-forward each previously sized every trade against the *full* bankroll independently — a strategy fully invested in five overlapping markets could still size a sixth at full Kelly, implying multi-x leverage that no live single-account execution could ever achieve. The unconstrained backtest was reporting fantasy PnL whenever positions overlapped. `run_backtest` and `run_backtest_walk_forward` both gain a `portfolio_constrained: bool = True` parameter. With the constraint on: events are processed in chronological order, available cash is tracked, each new stake is capped at `min(desired, cash)`, and resolved positions return their proceeds to the pool before the next decision. The Kelly fraction is still computed against the configured bankroll so fractions stay comparable to live Kelly usage; the constraint bites at the dollar level. New fields on `BacktestResult`: `portfolio_constrained` / `min_cash_seen` (trough of cash trajectory) / `n_clipped_for_cash` (trades smaller than Kelly-desired) / `n_skipped_for_cash` (would-be trades that got $0). Warnings surface both clipping and skipping so users can tell when bankroll is too small for the strategy's concurrent exposure. The unconstrained number was the fantasy this commit fixes. ### Changed

- **Order-book archive switched to WAL + batched cycle writes.** Two small tweaks that matter once the archive lives on a spinning disk (or grows beyond what the OS page cache holds hot): `book_archive._connect()` now sets `PRAGMA journal_mode=WAL` (persisted to the DB file) and `PRAGMA synchronous=NORMAL` (per-connection). WAL converts SQLite's random rollback-journal writes into sequential WAL appends; NORMAL drops the fsync from every commit to checkpoint-time — durable across an app crash but not a power loss, which is the right trade for an order-book archive (a lost few seconds gets recaptured next cycle). New `store_snapshots(snapshots)` batch helper writes a list of rows in one transaction; the poller now collects per-cycle snapshots into a list and flushes them in one call instead of N individual writes. Measured speedup on SSD: 100 inserts go from 94 ms (single-row) to 22 ms (batched) — **4.3×**. On HDD the speedup is larger because per-row fsyncs are ~10ms each vs ~0.1ms on SSD. 4 new tests cover the bulk-insert happy path, empty-batch, per-row custom timestamps, bad-row-skipped-rest-succeed, plus two pragma verification tests (WAL persists in the file across connections; synchronous=NORMAL on our connections). One existing poller test reinforced: `test_uses_batch_helper_not_per_row` asserts the cycle path uses the batch API exactly once per provider — guards against a regression silently reverting to the slow path.

### Changed

- **Backtest PnL now models transaction costs.** `run_backtest` gained `half_spread` (absolute price units per side, default 0.005 = half a cent — typical for liquid prediction markets) and `fee_pct` (fraction of stake, default 0). ### Notable design decisions

- **Multi-page via `st.navigation`** rather than `if/elif` switching — each page is its own file under `pages/` with shared utilities in `shared.py`
- **REST polling for the live ticker** rather than true WebSocket — `@st.fragment(run_every=3)` delivers indistinguishable UX for a single-user local app with much less complexity. Upgrade path to WebSocket documented in the developer guide.
- **JSON-serializable Kelly result** — early versions returned lambdas; replaced with plain floats so the result can be persisted/transmitted without custom handling
- **No order placement, no auth** — keeps the app read-only and runnable without keys; placing orders would require Polymarket API credentials + a Polygon wallet, both of which are out of scope for v0.x

### Known limitations

- `scan_price_divergence` is binary-markets-only by design (per-outcome last-trade data not yet collected)
- Live price ticker is REST-poll based, not push-based
- No order book depth fetch in parallel — sequential per-outcome
- No event-grouping UI (markets and events are joined for categorization but not for display)
- No realized-positions auto-close when markets resolve — user manually records the sell
