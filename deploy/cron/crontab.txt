# Managed-exits sibling profiles — cron entries
# ────────────────────────────────────────────────────────
# Each line mirrors an existing agentic profile cron entry but adds
# the full exit-management stack (TP/SL/vol-aware-trail/time-stop +
# two-stage TP). The original unmanaged profile keeps running so we
# get A/B head-to-head data.
#
# What changed since the first draft:
#   - TP thresholds are NET of Kalshi fees now, so gross gain has to
#     clear the fee drag (effective ~5–7pp tighter). The previous 0.30
#     gross-equivalent threshold is roughly 0.25 net at typical prices.
#   - --tp-to-trail-stop-pct 0.05 enables two-stage TP: hitting the TP
#     threshold ARMS a tight 5%-off-peak trail instead of selling.
#     Lets winners ride when momentum continues.
#   - --trail-stop-atr-mult 2.0 is the volatility-aware trail. It uses
#     K × σ of recent realized vol off peak instead of a fixed pct.
#     Quiet markets get a tight trail; jumpy markets get room. Composes
#     with the fixed --trail-stop-pct (whichever fires first wins).
#   - --trail-vol-window-hours: 24 for fast markets (baseball/llm), 48
#     for slower (consensus/favorites).
#
# Cost note: --trail-stop-atr-mult costs one extra get_price_history
# call per open position per cycle. Keep position counts reasonable.
